### OL-052 — Bounce / redirect (mutt-style resend) (built 2026-11-12, needs `./build.sh --live`; not run in the live UI, never sent)
- **Finding:** neither provider can bounce for real. Gmail `messages.send` and Exchange `sendMail` both take the recipients from the To / Cc / Bcc headers (there is no separate envelope) and send as the signed-in mailbox, so a resend can never keep the original From. Exchange has no resend action either (`forward` / `createForward` add the `FW:` subject, a header block and the user's text).
- **Built (the honest equivalent, both providers alike):** `B` / `:bounce a@x.org, b@y.org` -> a question that says exactly what the recipients get: *a message from you (own address), not from the original sender; Gmail and Exchange cannot send as someone else; subject, text and attachments unchanged; replies go to the original sender; original recipients not copied; goes out in N s, `u` takes it back*. Then it is queued as `kind: "bounce"` through the normal outbox, so the undo window and the failure pill apply (an undone or dismissed bounce is not reopened in the editor: `B` again). `src/bounce.rs` rewrites the original's source: body and files byte for byte; From, To / Cc, Date, Message-ID replaced; Reply-To = original Reply-To else original From; `X-Original-From`, `Resent-From/To/Date` added; DKIM / ARC / Received / Return-Path / read-receipt requests dropped. Gmail fetches `format=raw` and uploads the result; Exchange reads `/me/messages/{id}/$value` and sends it as MIME `sendMail` (refused above ~3 MB with the advice to forward). `/compose/send` refuses a bounce with files, Bcc or another From.
- **Checked:** unit tests (header rewrite incl. folded headers, LF-only mail, injection in a name / date, Reply-To rules, validation of the bounce message), `tests/bounce.test.js` (parsing, dialog text, message), qmllint, `node tests/commands.test.js` (`B` is free in the mail scope). Live read-only: a real Gmail message fetched as `format=raw` and run through the rewrite: body identical, transport headers replaced. **Not verified:** any actual send, so what a recipient's client shows, whether Gmail keeps or rewrites the headers, and whether Exchange accepts MIME `sendMail` for this tenant (the Graph `$value` read probe got 502/503 from Graph twice and was not repeated); the dialog and key in the running UI.

### OL-027 — Reading pane re-renders an already rendered message (fixed, tested in live 2026-10-30)
- **Seen:** 2026-10-26: with the window open the preview sometimes redraws on its own.
- **Cause:** `MessagePreview` runs `_invalidate()` (drops the render, settles 150 ms, re-runs the worker and the WebKit helper) on every `onBodyChanged`, and QML fires that on any assignment of `AppState.currentBody`, identical or not. `loadBody()` assigned a fresh object whenever the selected id was re-announced: `loadMessages()` does `clear()` + `append()` (new mail, folder reload), so `currentMessageId` went X → "" → X. `refreshFolderCounts()` (every 20 s) also bumped `_readRev` unconditionally, re-creating `currentMessage` each tick.
- **Fix:** `_setBody()` assigns only when id/state/type/content differ; `onCurrentMessageIdChanged` ignores the transient "" during a model swap (`_reloadingModel`) and returns early when the body, invite and attachments already belong to that id; `refreshFolderCounts()` bumps `_readRev` only when a count changed. qmllint: no errors. Not run in the live UI.
- **Second cause (found after deploying the first fix):** `loadSenders()` runs on the 20 s timer and did `clear()` + `append()` on `senderModelObj`; `currentHtmlMode` / `currentImagesAllowed` read that model, so for a message from a sender with always-HTML or always-images they flipped off and on within one tick, and each flip ran `_invalidate()`. Now the model is left alone when the `/settings/senders` response is unchanged.
- **Not covered:** when new mail lands at the top, the list reload keeps `msgIndex`, so the cursor then points at a different message and the pane legitimately switches to it.

### OL-019 — Recipients (To/Cc/Bcc) blank on some messages (fixed 2026-10-24, tested in live 2026-10-30)
- **Seen:** 2026-10-24: today's "Holiday party" from Erika showed no recipients; Graph has To = Jennifer Jackson, Gary Nusbaum, Adam. 78 other cached rows had the same (no conversation id).

### OL-004 — quickshell SIGSEGV opening HTML mail with remote images (fixed 2026-10-10)
- **Seen:** crash report `~/.cache/quickshell/crashes/6v922t8npmt` (pid 3468927): SIGSEGV in `QUrl::resolved` <- `QTextDocument::resource` <- `QQuickText::resourceRequestFinished`, right after `Connection refused` / `QSslSocket: device not open` from the HTML `Text` in `MessagePreview.qml`.
- **Cause:** Qt's `Text.RichText` fetches remote `<img>` (and `background=`) itself; the completion callback crashes when the request fails or the text has changed meanwhile. Marketing mail with tracking pixels triggers it.
- **Fix:** `Fmt.sanitizeHtml` never passes Qt a remote URL any more: allowed remote images become `[alt]` links opened in the browser; `background`/`srcset`/`poster` attributes are stripped. data: images still render inline.

### OL-002 — HTML rendering is not correct (fixed 2026-10-10 with a WebKitGTK helper)
- **Cause:** Qt `Text.RichText` has no `border-radius`, `box-shadow`, inline-block layout or `<style>` support, so styled mail (Stripe receipts, newsletters) came out as flat boxes with collapsed columns.
- **Fix:** `tools/render/omalook-render.c` (WebKitGTK 4.1, ~200 lines of C) renders the HTML to a PNG plus link boxes in its own process; `MessagePreview.qml` shows the PNG with a click area per link. A GTK widget cannot be embedded in a Quickshell window on Wayland, so a separate process is the embedding. Crash/hang/timeout (20 s) of the helper only means that message falls back to the Qt renderer; 3 failures disable the helper for the session.
- **Isolation:** ephemeral WebKit data (no cookies/cache), page JS blocked (CSP `script-src 'none'` + only our own link query runs), navigation and popups denied, no remote loads unless `--images` (message/sender allowed).
- **Build/ship:** `build.sh` compiles it to `bin/` when `webkit2gtk-4.1`, gtk3 and gcc exist (else a warning and Qt fallback); `--live` installs it to `/opt/omalook/bin`. Runtime needs `libwebkit2gtk-4.1` (Arch: `webkit2gtk-4.1`).
- **Known limits:** no text selection in the WebKit view (use the System view to copy text); blocked remote images show as WebKit's empty image boxes; re-renders on every selection/resize (no cache yet).
