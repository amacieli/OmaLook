### OL-034 — Messages deleted on another client disappear from OmaLook (done 2026-10-31, commit 5b21dc8, tested live by user)
- **Symptom:** a message deleted elsewhere stayed in the list for hours until a manual refresh.
- **Causes:** (1) Gmail sync never looked for deletions. (2) Exchange removals were already applied by the Graph delta feed, but `refreshMessages()` (OL-033) only handled new mail and reloaded on other changes only while 200 or fewer rows were loaded, so a deeper list never dropped the row.
- **Fix:** `EmailProvider::fetch_all_ids` (Gmail pages through ids; a partial list is an error) + `Database::reconcile_deleted` (skips rows with an unpushed read change), run on the first non-delta cycle and every 5th after it (about 5 min at 60 s). `refreshMessages()` now removes just the rows the server no longer returns, at any scroll depth, and keeps the cursor on the same message. The daemon also polls the Inbox alone every 10 s between full cycles (`INBOX_POLL_SECS`; delta for Graph, list + read state + deleted reconcile for Gmail).
- **Checked:** 342 lib tests pass (none cover the new code); user deleted a message elsewhere and saw it disappear. Push notifications (Graph subscriptions, Gmail `users.watch` + Pub/Sub) were looked at and rejected: they need a public endpoint or a per-user cloud project.

### OL-027 — Reading pane re-renders an already rendered message (fixed, tested in live 2026-10-30)
- **Seen:** 2026-10-26: with the window open the preview sometimes redraws on its own.
- **Cause:** `MessagePreview` runs `_invalidate()` (drops the render, settles 150 ms, re-runs the worker and the WebKit helper) on every `onBodyChanged`, and QML fires that on any assignment of `AppState.currentBody`, identical or not. `loadBody()` assigned a fresh object whenever the selected id was re-announced: `loadMessages()` does `clear()` + `append()` (new mail, folder reload), so `currentMessageId` went X → "" → X. `refreshFolderCounts()` (every 20 s) also bumped `_readRev` unconditionally, re-creating `currentMessage` each tick.
- **Fix:** `_setBody()` assigns only when id/state/type/content differ; `onCurrentMessageIdChanged` ignores the transient "" during a model swap (`_reloadingModel`) and returns early when the body, invite and attachments already belong to that id; `refreshFolderCounts()` bumps `_readRev` only when a count changed. qmllint: no errors. Not run in the live UI.
- **Second cause (found after deploying the first fix):** `loadSenders()` runs on the 20 s timer and did `clear()` + `append()` on `senderModelObj`; `currentHtmlMode` / `currentImagesAllowed` read that model, so for a message from a sender with always-HTML or always-images they flipped off and on within one tick, and each flip ran `_invalidate()`. Now the model is left alone when the `/settings/senders` response is unchanged.
- **Not covered:** when new mail lands at the top, the list reload keeps `msgIndex`, so the cursor then points at a different message and the pane legitimately switches to it.

- **Known limits:** no text selection in the WebKit view (use the System view to copy text); blocked remote images show as WebKit's empty image boxes; re-renders on every selection/resize (no cache yet).
